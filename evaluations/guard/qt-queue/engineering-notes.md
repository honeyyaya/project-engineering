## Project facts / Requirement

目标是演示 PERF-002 无界队列风险从测试证据到修复复核的闭环。输入来自测试内生成的整数，队列只在调用线程内使用，不承担实际帧内存所有权。

验收：空队列 pop 返回 false 且不修改输出；未满时先进先出；容量必须大于零，否则抛出 invalid_argument；满载时丢弃最旧项；容量为 4 时连续生产 10,000 条且不消费，每次 push 后均不超过 4，最后依序取出 9996、9997、9998、9999。

非目标：视频处理、业务项目重构、端到端延迟、并发安全、线程调度、网络、安全边界、持久化、上线发布。队列数量有界不等于内存或延迟预算达标。

工具链实测见 `.engineering/evidence/toolchain.txt`、`configure.txt` 和 `build.txt`。本机 QtCore 的 qqueue.h 许可标记及文件散列已记录；未审核 SDK 二进制供应链、补丁状况和发布许可条件。交付只含自行编写的源码及验证记录，未复制 Qt 源码、头文件或运行库。未来引入发布需求时增加 release 特征并重新审查。

## Architecture

构建依赖为 `queue_tests → src/frame_queue.h → Qt5::Core`；对照程序为 `queue_negative_control → negative-control/frame_queue.h → Qt5::Core`。两者共用测试文件，但目标的 include 路径独立，不同时链接两份实现。不存在模块相互依赖或上层库反向依赖测试程序。

风险假设：对照实现仅调用 enqueue，没有保存和检查容量。持续生产快于消费时，size 随累计输入增长。本次通过 10,000 次生产、0 次消费验证这个已知缺陷，而非声称 Agent 自主发现了未知缺陷。

## Design / Interfaces

FrameQueue 持有 QQueue<int> 值成员；构造、析构和存储由对象生命周期管理，无裸指针所有权、QObject parent 或跨线程回调。调用方负责不跨线程并发访问。

接口为 `FrameQueue(int capacity)`、`push(int)`、`pop(int&) -> bool`、`size() -> int`。容量只能为正；push 达到容量时先出队最旧项再入队；空 pop 不写输出值。这里选择丢弃最旧值是为保留最新编号，业务若不允许丢失，必须改为背压或其他策略并重写验收。

异常约定：非法容量抛出 invalid_argument；没有承诺在分配失败时保持队列内容完全不变。标准异常传播给调用者，本实验不提供进程级故障恢复。

## Plan / Test plan

最小步骤是：制定可观察容量契约；构造有缺陷的对照输入；用同一测试检查两份实现；实现固定容量与丢弃策略；记录失败、成功和剩余范围；用门禁检查风险状态。

测试映射：empty 检查空队列与输出不变；fifo 检查正常顺序；capacity 检查容量 1 时保留最新项；zero 检查 0 和负容量；overload 检查每次 push 的数量上限及最后保留的编号。显式返回测试失败码，不依赖 Release 中可能关闭的 assert。
