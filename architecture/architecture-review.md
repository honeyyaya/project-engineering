# Architecture Analysis

用于理解系统当前形态并判断变更会如何传播。

## 分析顺序

1. 画出实际模块、层、进程/线程和外部系统；以代码、构建文件和运行配置为证据。
2. 标记关键入口、数据源、状态持有者、同步边界和失败路径。
3. 对照目标与约束，列出耦合点、单向依赖被破坏的位置、隐式契约和演进风险。
4. 比较至少一个可行替代方案，说明收益、代价、迁移步骤和回滚条件。

## 输出

优先输出事实与风险，再输出建议。每项风险说明影响面、发生条件和置信度；架构结论需要能落到模块、接口或构建依赖上。重大决策使用 [ADR 模板](../templates/ADR.md)。
