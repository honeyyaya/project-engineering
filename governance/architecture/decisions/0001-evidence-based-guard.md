# ADR-0001：以项目本地证据连接跨阶段风险检查

- 状态：已采纳，实验性实现
- 日期：2026-09-10
- 背景：已有能力目录、Profile 和八阶段 Workflow，但缺少可执行的风险检查记录。需要在真实项目中识别遗漏、确定责任并复核措施。
- 决策：沿用 Role / Skill / Standard / Workflow / Superpower 五类。Guardian 是横切 Role；风险目录与门禁配置属于管理基础设施。`registry/risks.yaml` 保存可复用规则，目标项目 `.engineering/run.yaml` 保存检查和具体问题。Explorer 提供事实，专业角色完成分析，Guardian 检查遗漏及关闭证据。
- 执行边界：Agent 在阶段边界及范围、依赖、线程、测试结果改变时调用检查器。脚本只核对记录、文件散列、版本和未关闭风险，不判断报告语义、不自动分析 C++、不常驻调度。
- 采用策略：Profile 的 `always`/`required` 改为 `candidates`；Skill Registry 的 `profile_default` 改为 `profile_candidate`。候选、采用关系与成熟度分开，S1 显式参考/评估，S4 才允许默认启用。
- 替代方案：仅增加 Markdown 清单无法自动发现缺证据；直接构建完整调度/扫描平台缺少真实案例依据。当前选择薄检查器与人工/Agent 语义复核结合。
- 影响：可以阻断缺失、过期证据及未处理的高风险；仍依赖正确的特征识别、问题登记和诚实审查。散列不能证明报告真实或覆盖充分，阶段版本由执行者维护。
- 迁移与回滚：旧 Profile 消费者改读候选字段并显式选用组件；目标项目首次初始化记录，补齐真实证据前不得视为通过。可停用 CLI 并保留记录供人工检查，目标业务代码不依赖管理器。
- 验证：门禁单元测试和 [Qt 队列对照实验](../../../evaluations/guard/README.md)。本实验不晋升上游组件成熟度。
